# 知序 · 电力系统分析学习工作台

面向电力系统分析学习的本地网页：拍照输入题目，查阅学科 Wiki，积累个人关联题目，再按真实记录回顾原题。

## 启动

macOS 双击 `start.command`，访问 http://127.0.0.1:8765 。保留终端窗口；Ctrl+C 停止服务。

首次需要 Python 3.9+、Node.js 22+ 和网络。手动启动：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm --prefix web ci
npm --prefix web run build
.venv/bin/python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8765
```

## 三个工作区

- **学习台**：上传 HEIC/PNG/JPEG/WebP 图片，支持未作答题；先显示识别结果，再检索 Wiki 独立解题。照片已有作答时直接显示对错，不要求重复提交；完整解析保持收起，可选择“查看解析”或“给我一点提示”。可编辑题干、选项、图片里的答案，补充依据复核。
- **知识库**：6 个章节、18 个稳定 ID 的知识点骨架。所有正文初始为草稿空态；按章节或关键词查找，查看正文、来源、关系与个人关联题目。可从知识点直接开始学习对话。
- **复习**：对个人历史原题安排回顾。开始时隐藏答案，提交后显示结果；提前练习、辅助作答和原题性质均明确标记。

不预置题库，不自动生成变式，不诊断心理错因，不要求手写思路或填写信心，不提供掌握率/遗忘率。核心知识不会被模型自动改写。

新学习在首次上传/发起对话时创建，默认名为 `电力系统分析1 · 260916`，按北京时间每天重新编号；删除不会回收编号。标题旁可手动改名，已有历史名称不自动覆盖。

图片一次最多 12 张，每次学习最多 24 张未清理原图，输入单图上限 50 MB。macOS 上 HEIC 和超过 12 MB 的普通图片通过本机 sips 转为最长边 3200 像素的 JPEG，转换结果不超过 12 MB；不修改电脑上的源文件，不使用第三方转换网站。其他操作系统目前需先自行导出 JPEG，界面会给出明确提示。

识别要求继承单选/多选分区标题，并标记页底、边缘缺失的题干、选项和必要图形。标记残缺或仅剩一个可见选项的选择题不自动核对、不计入复习证据；需重新拍照，或编辑补全并明确勾选已核对完整。普通文字修改不会自动解除残缺标记。识别与模型答案仍可能出错，应以原图和可靠教材核对。

“给我一点提示”按题按修订版本生成并缓存，后续可在该题讨论中继续请求提示；点击查看解析后可正常深入讨论。题目讨论按题目 ID 与修订号隔离，最近 12 条本题消息进入模型上下文；取消选题进入公共讨论。旧无题目标签的聊天保留在公共讨论，不自动归入某题。提示使用已有解答核验方向，并拦截常见直接给选项的输出，但不保证语义上绝不泄露答案；判断题显示对错本身就可能透露答案。

## 填充知识库

请先阅读 [knowledge/README.md](knowledge/README.md)。

- 目录、章节、别名和关系：`knowledge/catalog.json`。
- 正文：`knowledge/nodes/*.md`。
- 编写模板：`knowledge/TEMPLATE.md`。
- 发布前校验：`.venv/bin/python -m app.validate_knowledge`。

填充正文、写明来源并审核后，将该节点设为 published；修改后递增 version。草稿不进入模型讲解上下文。尚无正文时仍可挂载题目，讲解明确标记“模型补充”。

知识检索固定在解题/交流之前；引用记录实际提供给模型的节点和版本，不把检索命中等同于解题正确。初始目录是可维护的范围骨架，不宣称等同于最新官方考纲。

## 个人挂载与学习记录

公共知识文件和个人学习数据库分开。题目通过稳定知识 ID 多对多关联，题目卡片可修正或解除关联；没有匹配项时保留待归类，不凭模型输出自动创建公共节点。

个人事件区分：

- 照片中已有作答：帮助情况未知。
- 保存题目、打开讲解：没有作答就不记录答对。
- 站内提交：记录实际答案，保留照片里的首次答案。看过提示或已知道照片作答对错后的主动重答，按辅助作答处理。修改识别内容会撤销旧判定，但不会抹去近期看过提示/解析的事实。
- 原题复习：独立/辅助分别记录。24 小时内查看过同题讲解，按辅助作答处理；不同页面同时复习时，打开原题答案也会影响辅助标记。

复习是可解释的规则基线：初次解答后 1 天回顾；有效独立复习按跨日成功次数使用 1/3/7/14/30 天间隔；答错或得到帮助后答对，回到 1 天。当天反复作答不堆叠延长间隔。到期只表示建议回顾，不表示已经遗忘；同题表现不等于陌生题迁移能力。

修改题目或提出依据复核，会撤销该题原有事件判断，使已开启的旧复习失效；新解答成功后再重新安排。历史判断仍保存在数据库中供回溯，不复用已撤销事件。

## 模型设置

连接 OpenAI-compatible Chat Completions 服务；分别指定图片识别、解题、学习对话三个任务。保留模型配置、按模型并发、请求速率限制、结构化校验与有限重试。图片识别要求模型支持 image_url。保存并测试只验证文本连接，实际识图/学科质量需用自己的模型和题目验证。

图片识别支持流式 NDJSON。当前本机视觉配置为官方 DeepSeek V4.1 Flash（`https://api.deepseek.com`，模型 ID `deepseek-flash`）；配置模板不包含密钥。

网页使用后台流水线：完整识别出第一题后立即单题核对，其他题目按最多 3 题一组批量处理；默认 2 个后台求解槽位，跨学习会话共享，显式模型并发配置优先。批量缺失、无效或待确认项只单独重试该题一次，仍不确定就保留待确认。已确认题目不会在重试整次学习时重复解答。GLM 5.3 使用低推理强度与有界输出长度；并非无限并发，服务限流仍会影响耗时。

后台不锁住整页：已完成题可查看对错、解析、提示、重答和追问，剩余题继续处理；主动交互期间暂停启动新的后台解题请求，已经发出的请求不强行中断。编辑题干、关联、参考资料与删除等结构性操作需等后台结束。关掉页面不会取消后台任务，停止本地服务则保留结果并在下次启动提示重试。前端只轮询当前学习的进度，不重复发起计算、不自动切题或滚动。

普通追问和“详细展开这份解析”使用真实流式输出，初始解析为简短关键依据。提示及提示后续对话先完整生成并检查后再显示，避免先流出答案再拦截。连接中断或输出截断不会保存为完整助手回答；已展示的部分内容仍记为获得帮助。`job_metrics` 保留本次后台任务首个可用结果与总耗时（毫秒），不包含图片上传耗时；真实效果需按图片/模型实测。

没有内置密钥，也不会扫描其他应用。配置与记录保存在本机；使用模型时，相关图片、题目、知识片段和历史会发送给配置的模型服务。密钥通过文件权限保护，并非数据库加密。

## 旧数据与本次升级

原数据库与原图保留。旧诊断不会转成新的学习状态；旧题显示历史标记，可主动重新解答后进入新流程。旧的五任务配置读取为三任务，已有模型与密钥保留。移除了旧版演示、生成题与自动诊断的活跃接口和页面。

数据库默认在 `data/learning.sqlite3`，原图在 `data/attachments/`。设置 `GRID_LEARNING_DATA` 可指定其他目录。备份前停止服务，复制整个 data 目录；不要忽略 WAL 文件。网页删除学习会同时删除个人题目挂载、复习记录和原图，核心知识不受影响。

## 服务与部署边界

此版本是**本地单用户框架**。核心知识服务见 `app/knowledge.py`，个人事件/复习服务见 `app/study.py`，接口文档见 /api/docs。已经分离服务职责，便于后续接入远程知识服务或 MCP。

**尚未实现远程 MCP、付费服务、多用户账户和知识库服务端保密。** 本地知识文件对本机用户可见，不能直接作为保密内容分发方案。不要将本地服务端口直接对公网开放。
