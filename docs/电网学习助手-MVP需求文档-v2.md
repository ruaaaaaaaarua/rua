# 电网学习助手 — MVP 需求文档 v2

版本日期：2026-09-09  
文档状态：根据完整需求讨论整理的建设依据。当前仅整理需求，开发须等待用户另行要求。  
适用范围：单用户、个人学习、电脑端网页；程序与学习记录保存在本机，通过 API 使用云端模型。

## 1. 产品目标

构建一个以用户真实刷题过程为入口、能够跨多次学习持续更新认知判断的电网专业课学习助手。

用户在纸上做题，鼓励留下公式、关键步骤或简短判断依据，随后上传整页照片。助手先独立解答，再分析用户的答案和思路，给出整页总览、正确题的一句话知识点，以及错误或犹豫题的简短反馈。用户按需追问、查看详细解析、练变式或验证基础知识。

长期积累的核心是：用户对哪些知识有理解证据、可能混淆什么、哪些疑点已经验证、哪些还需要观察。题目是诊断材料，不建设独立题库产品，也不要求用户归档和维护大量题目。

成功标准：用户阅读负担低、交流顺畅；诊断有依据；后续刷题能够联系历史，并根据新证据修正判断。

“认知诊断”指根据可观察的答题与交流推断知识状态，不能直接测量大脑。没有证据的知识应显示尚无记录，不使用没有依据的精确掌握率、遗忘率或“认知数字孪生”预测。

## 2. 第一版范围

### 2.1 包含

- 单选、多选、判断题；选择题中可以包含计算。
- 文字类题目为主，识别手写选项、公式、关键思路、犹豫与猜测标记。
- 已作答的整页图片上传、多图上传、原图对照及识别内容修改。
- AI 独立解题、参考答案可选、整页分析与简短反馈。
- 围绕任意题目的自由追问，包括答对的题。
- 提示优先与直接纠错两种偏好，随时切换。
- 用户主动选择的最小变式、复测、基础知识验证、深入测试。
- 跨次学习的知识状态、证据、变化记录和简洁面板。
- 科目与章节粗框架、逐步补充知识点及直接相关的前置关联。
- 覆盖备考涉及的全部专业科目，共用流程；不限定先做单科。
- 本地历史、自动保存、纠错和相关学习状态修正。
- 按任务手动配置模型、结构化输出、变式展示前复核。
- 对话中按需补充文字、截图或相关页面作为参考。
- 后续可补充考纲、考点与考频信息，不作为开始使用的前提。

### 2.2 第一版不做

- 上传尚未作答的原题并在网页完成原题作答。AI 变式仍可在线回答；提示后修改已有答案不受此限制。
- 独立题库页面、批量题库导入、自动题库匹配、整套 AI 题库生成。
- 完整教材资料库及通用批量检索平台。
- 预先穷尽全部知识的完整图谱。
- 自动每日学习计划、固定间隔复习日程、外部通知或每次开始刷题时的主动推荐。
- 按任务难度、价格自动挑选或升级模型。
- 通用符号求解和自动计算验证系统；基础模型复核属于必需功能。
- 多用户、账号权限、教师后台、支付、社区、排行榜。
- 复杂数据大屏、Obsidian 同步、无限自主训练或递归追溯基础。
- 独立的复杂电路图编辑、重绘和图形处理系统。

## 3. 核心使用流程

### 3.1 纸质做题与上传

用户先在纸上完成题目，再拖拽或选择图片上传。鼓励但不强制写关键思路，不要求完整思维过程。

允许的表达示例：

```text
12. C，使用公式……
13. B ?
14. A / C 纠结
15. AC，猜的
16. √
```

系统区分确定、犹豫、猜测、未提供。未标犹豫不代表有证据证明用户确定或掌握，只影响默认是否需要停下来处理。

### 3.2 识别与独立解题

1. 图片理解模型提取题目与用户作答，二者分别保存。
2. 保留题号、题干、选项、公式、单位、关键图形、用户答案、思路、涂改及不确定处。
3. 推理模型先根据题目独立求解，再比对用户答案与思路，避免受用户选项影响。
4. 有参考答案或解析时参与核对；没有时使用 AI 自解结果，并标明来源。
5. 直接展示整页结果，不强制经过整页识别确认步骤。

用户随时可修改识别内容。模型发现疑点时可返回原图局部复核；仍不清楚时只询问相关题目或请求补拍，其余题目继续处理。无法可靠作答的题标为待确认，不强行判错。

### 3.3 整页反馈顺序

默认一次集中展示整页，不能自动逐题进入长解析。

**第一部分：整页总览。** 展示已判定的答对、答错，以及待确认情况。犹豫和猜测是可以与对错重叠的标记，不作为互斥计数。

示例：

> 本页 10 题：答对 8 题，其中 1 题犹豫；答错 2 题。

**第二部分：直接通过的题。** 答案和已提供思路正确、无犹豫的题，每题用一句话带过关键知识点，不展开推导。答对但未写思路、未标犹豫的题，也直接通过并给一句知识点；只记录本题表现，不据此认定掌握。

**第三部分：错误或犹豫等需要关注的题。** 集中展示简短诊断或辨析，随后由用户决定处理哪道题。

| 情况 | 默认反馈 |
| --- | --- |
| 答错且原因有证据 | 指出具体错误，按反馈偏好给提示或纠错 |
| 答错但原因不明 | 说明疑点，必要时提出一句针对性追问，不编造错误位置 |
| 答对但思路有误 | 一句话指出思路问题，不因选项正确而忽略 |
| 答对但犹豫 | 直接给简短辨析，不只提示“需要区分” |
| 只标问号、未写纠结点 | 简短说明关键判断依据，不假定纠结于哪两个选项 |
| 猜对 | 给关键依据并保留猜测标记，不认定掌握，不强制测试 |
| 答错且犹豫 | 合并纠错与辨析，避免重复；提示优先时不提前揭晓 |
| 题目或答案有争议 | 标为待确认，暂不更新知识状态 |

整页可能包含多条“一句话知识点”，不受原文“每次最多 1～5 句话”的硬限制。短反馈强调每条信息必要、精炼，而非省略已约定的整页内容。

### 3.4 后续交流

用户可以点击题目，也可以说“解释第 5 题”“为什么 C 不对”“我这个公式哪里错了”“换个说法”。助手保留当前题目及相关对话背景，明确当前讨论对象。

不强制逐个处理所有错题。任何题均可追问、看解析或练变式。用户可以继续、跳过、返回或结束。

“下一题”默认指本次上传的下一道原题，是用户主动导航，不触发默认逐题解析；“再来一道”在训练语境中默认继续当前知识点。语境不足时简短确认目标。

## 4. 反馈与阅读负担

### 4.1 两种反馈偏好

| 场景 | 提示优先 | 直接纠错 |
| --- | --- | --- |
| 正确、无犹豫 | 一句话知识点 | 相同 |
| 正确但犹豫 | 简短辨析 | 相同 |
| 答错 | 指出检查方向，暂不公开正确选项及完整解法 | 公布答案，简短指出问题 |
| 答错且犹豫 | 围绕纠结点给提示，避免直接推出答案 | 简短纠错并辨析 |

刷题界面可随时切换，立即影响之后的反馈，记住上次选择。已揭晓的内容不因切换而重新隐藏。提示优先时可随时看答案，也可提交修改后的答案。

整页相关题目的反馈应尽量避免直接泄露待重试题的答案。如果已经看到相关提示或解法，后续作答按实际帮助情况记录，不能算完全独立验证。

### 4.2 解释深度

- 默认只说当前必要的信息，不自动长篇授课或频繁鼓励。
- 用户主动看解析或追问时可以展开，不要求连续答错才解锁详细讲解。
- 用户只问一个选项或一个步骤，就围绕该点回答，不重讲整题。
- 用户说没懂时，换一种解释或拆小问题，不机械地加字数。
- 连续答错时按卡点逐步帮助，不自动输出 100～200 字或更长文章。
- 诊断追问可以跳过。跳过后可直接看简短解法，错误原因保留未确定。

原文 Level 0～3 不再作为按错误次数自动升级篇幅、强制出题的状态机。

## 5. 判定与诊断规则

### 5.1 题型与作答

- 单选：选项与可用答案一致则答对。
- 多选：全部选项一致才算答对，忽略顺序；区分漏选、错选、两者都有。
- 判断：支持对/错、√/× 等常见表达。
- 计算是内容特征，可与单选或多选共存；同时观察公式、代入、单位和计算步骤。
- 第一版统计作答表现，不做具体考试的分数折算。
- 首次答案、提示后重答、变式作答分别记录，不能用后一次答对覆盖第一次表现。

漏选、错选是作答结果，不等于认知原因。

### 5.2 诊断的三层信息

| 层次 | 示例 |
| --- | --- |
| 涉及知识 | 某公式的适用条件 |
| 可观察事实 | 公式写对，但使用时忽略题目限制条件 |
| 待验证推断 | 可能未分清适用边界 |

可以使用概念、公式、条件、计算、单位、基准值、建模、推理、审题、记忆等结构化错误分类；允许无法确定，也允许一题涉及多处有依据的问题。分类不能替代具体诊断。

只有错误选项、没有思路时，通常不足以确定认知原因。推断应使用“可能”等表述并保存依据。用户犹豫与模型诊断不确定分开记录。

### 5.3 答案来源与纠错

区分题目来源、参考答案来源、AI 自解答案和后续修订。参考资料有冲突时核查具体依据，不盲从，也不把冲突归为用户不会。

用户可以质疑 AI 判断、修改识别结果、补充答案或资料。确认模型或识别错误后，明确更正作答判定，撤销或修正相关学习证据，并重新评估受影响知识状态。纠正系统记录不要求用户额外答题证明。

## 6. 变式、复测与深入测试

### 6.1 用户控制训练

变式、复测、基础验证和深入测试均由用户主动选择开始。助手可结合当前问题提出一个有理由的建议，但不自动出题，不在每次开始刷题时主动推荐，不因跳过反复催促。

变式答对后简短通过，不自动追加解析或下一道题；答错后简短提示或纠错，是否继续由用户决定。

用户说“懂了”可结束讲解，记录为用户表示理解，不等于验证通过。

### 6.2 最小变式

围绕当前题目和需要巩固或辨析的点生成，不限于错题。默认难度接近，一次尽量只改变一个需要重新判断的关键因素。

可采用换数值、已知未知互换、单一条件变化、概念与计算互换、反向推理、干扰项变化。文字题突出概念边界、适用条件及相近概念区分；仅换选项位置不视为充分的诊断设计。

形式以单选、多选、判断为主，也允许回答一个词、数值或一句话的简短问答。不默认要求完整解题过程。

不无理由增加复杂背景或相邻知识组合。保留原题关联、测试目标、改变的条件、答案与解析；完整解析不默认展示。

### 6.3 前置知识验证

结合当前思路及历史证据提出基础卡点假设，用户接受后给一个更基础的测试。通过则重新审视原诊断；未通过则简短处理具体问题，需要时再验证，之后回到原题。

第一版只追查直接相关的基础，不无限递归。AI 推测的前置关联需要核查，不能凭一次错误把整章标为薄弱。

### 6.4 深入测试

用户主动要求“深入测一下”等时，允许逐步改变条件或增加推理深度，一次一道、随时结束。记录能力在哪种条件下表现稳定、在哪种新条件下尚待验证。

探索性失败不抹掉基础能力证据，超出备考范围的探索不直接降低备考范围内的判断。

### 6.5 必需的质量复核

变式展示前必须复核，接受增加的模型调用和等待：

1. 先不向复核任务提供生成答案，重新解答题目，再比较结果。
2. 检查条件完整、题型与选项合法、答案与解析一致、测试目标仍然符合要求。
3. 单选检查唯一正确项，多选检查完整正确选项集合，判断题检查命题明确性。
4. 不通过则有限次重新生成，仍有疑点则停止并简短说明，不能将失败题当作有效学习证据。
5. 后续确认题目有错时撤销对知识状态的影响。

可以用主模型复核，也可指定其他模型。重复复核或多个模型一致均不保证正确；模型分歧应检查依据，不能投票或默认贵的正确。

## 7. 持续知识状态

### 7.1 知识框架

采用科目 → 章节 → 知识点的粗框架，各科共用流程，知识点随刷题细化。同一知识点的不同表述归并，避免重复积累。跨科基础知识可建立关联，但判断必须有对应证据。

未涉及的知识显示尚无记录。没有考纲时可开始使用；以后补充大纲或目录再调整组织方式，不删除既有证据。

### 7.2 需要保存的证据

- 涉及知识、适用条件与测试目标。
- 时间、作答结果、用户公式或简短依据、犹豫或猜测标记。
- 可观察事实、诊断推断、支持依据及不确定处。
- 是否独立作答、是否得到提示、是否刚看过相关解析。
- 原题、变式、复测或深入测试的性质。
- 后续验证、判断变化、更正及撤销记录。
- 对应历史对话或必要题目片段的关联。

保存诊断所需信息，不建设独立题库，不默认记录无法可靠测得的答题耗时。

### 7.3 更新规则

- 单次答对可以通过当前题，不等于掌握整个知识点。
- 正确关键思路、不同条件下的独立表现、间隔后的表现提供不同强度的证据。
- 提示后答对、刚看完解析后答对与独立答对分开记录。
- 新证据可以支持、收窄或推翻旧判断，保留变化原因。
- 时间久只提供复测理由，不自动认定遗忘。
- AI 答案有争议或识别未确认时，保留交流，暂不据此更新状态。
- 一次错误不自动降低整个章节或所有关联科目的状态。
- 状态变化不能只依赖模型自由文本，必须通过校验后的结构化记录更新。

### 7.4 知识状态面板

默认突出需要关注的知识，其他按需展开。每个知识点显示：具体判断、依据摘要、最近验证情况、变化记录和操作入口。

示例：

> **公式适用条件：待验证**  
> 能正确代入，但两次忽略限制条件；最近一次在提示后答对。

“疑似混淆”与“提示后通过”等验证情况分开显示，不强塞进一个单一等级。可使用尚无记录、证据不足、待验证、独立验证通过、表现较稳定等可解释描述，不承诺精确百分比分数。

操作包括查看依据、验证一下、反馈记录错误。用户不能手动把状态改成已掌握；认为已经会了，应通过针对性答题形成新证据。任意一道答对不自动验证所有疑点。

### 7.5 复测建议

结合当前题目或用户主动询问，优先考虑当前问题、反复混淆、影响多个问题的基础卡点、修正后尚未独立复测的疑点，再参考距上次验证时间。

每次最多突出一个建议并说明理由；不自动排每日任务，不套固定遗忘曲线，不在开始刷题时推荐，不对跳过建议反复催促。

## 8. 资料与考试范围

对话中允许补充文字、截图或相关页面，辅助当前核查；完整教材资料库暂缓。

后续补充考试信息时：考纲用于范围与框架，考点用于定位具体内容，考频作为建议优先级的参考，保留来源与年份。当前第一版不因缺少这些材料而阻塞。

考试重要程度与个人知识状态分别记录。考得多不等于薄弱，考得少不等于掌握；范围变更不删除历史学习依据。

## 9. 网页工作区

电脑端优先，借鉴 Codex 桌面端的布局和以对话为主的操作方式，用网页实现学习场景。

- 左侧：新建刷题对话、历史对话、知识状态与设置入口。不设置独立题库页面。
- 中间：上传、整页反馈、自由追问和可交互的变式题；支持点击操作和自然语言操作。
- 右侧：按需展示当前原图、题干、用户答案及手写思路，方便对照与修改。

不强制切换上传、确认、诊断、训练多个独立页面。对话中明确当前题目；详细解析折叠或按需展开。常用操作可以点击，不必全部打字。

## 10. 历史、本地存储与删除

历史对话默认长期保存在本机，自动保存，可回来继续。保留与诊断相关的题目内容及证据，原图可单独清理，不要求题库整理。

删除时提供两个范围：

1. 只删除对话和原图，默认保留提炼后的学习证据摘要，并标明原始记录已删除。
2. 同时删除相关学习证据，依据剩余证据重新评估知识状态；不足时退回待验证或无足够证据。

历史既能按对话回查，也能按知识点看变化。原题、变式、提示后重答分开统计；不混合生成虚高的正确率。待确认的题不混入已可靠判定的正确率。

不自动生成长篇结束报告。有值得记录的变化时可短句说明；本轮未再出现某错误，不直接视为已解决。

## 11. 按任务手动配置模型

### 11.1 任务与默认配置

默认界面配置图片模型和主模型，高级配置允许任务覆盖：

| 任务 | 默认 | 可单独指定 |
| --- | --- | --- |
| 图片理解与局部复核 | 图片模型 | 是 |
| 独立解题、诊断与知识状态提案 | 主模型 | 是 |
| 解释与自由追问 | 主模型 | 是 |
| 变式生成 | 主模型 | 是 |
| 变式复核 | 主模型 | 是 |

每个模型配置可选择服务商、接口地址、模型名称与 API Key。同一配置可以被多个任务复用，不要求配置多个不同模型。具体型号在建设与试用时按接口和实际能力选择，不预设某一服务商必然擅长某任务。

第一版不自动按价格、难度升级或切换模型。用户可手动修改任务配置或换模型重试；系统检查任务所需能力及配置是否可用。

### 11.2 成本与上下文

- 识图结果可复用，后续无需每次重发整页图片。
- 原图变更或识别内容更正时使相关缓存失效，重算受影响内容。
- 每次使用当前页信息、相关对话及相关知识状态摘要，不默认发送所有历史。
- 日常使用证据摘要，必要时回查对应记录，不将摘要压缩成没有依据的薄弱标签。
- 保留实际模型、任务及可获取的用量信息便于排查，不承诺未经测量的费用。
- 程序与记录本地保存不等于离线：相关题目、手写内容及必要历史会发给配置的云端模型处理。

### 11.3 可替换性

模型通过统一适配层调用，服务商差异不散布到核心流程。更换模型不影响历史、知识框架、证据和当前学习状态。

新模型不同意旧判断时提出带依据的修订，不能无依据覆盖历史。提示词、结构化协议和程序状态管理分开。

## 12. 系统职责与数据要求

以下为实现约束，不是要求立即选择框架或创建代码。

### 12.1 职责

- 输入处理：原图、识别结果、修改与局部复核。
- 学习对话：整页反馈、当前题目、用户偏好及连续交流。
- 解题诊断：独立求解、参考核对、事实与推断分离。
- 训练：按用户选择生成、复核、反馈与返回原题。
- 知识框架与学习状态：节点归并、证据、判断版本及相关前置关联。
- 本地存储：历史、附件、重试进度、删除与修正。
- 模型适配：任务配置、调用、结构化校验和有限重试。

不为“Agent”引入不必要的复杂框架。模型负责理解、推理和输出提案；程序负责持久状态、校验、关联更新、配置、重试和流程边界。

### 12.2 最少数据对象

| 对象 | 内容 |
| --- | --- |
| 刷题对话 | 时间、消息、附件、当前题目、反馈偏好、进度 |
| 题目快照 | 题号、题型、内容、选项、计算特征、原图关联、来源及识别修订 |
| 作答记录 | 首答或重答、答案、关键思路、犹豫、帮助情况、判定及依据 |
| 解答与诊断 | 自解或参考来源、答案、核查状态、事实、错误分类、推断、版本 |
| 验证任务 | 来源题目或知识疑点、目的、变式方式、题目、复核状态及结果 |
| 知识节点 | 科目章节、别名、范围及直接相关关联 |
| 学习证据 | 观察、条件、时间、独立程度、关联记录、有效或撤销状态 |
| 知识状态 | 具体判断、依据摘要、验证情况、变化及更新时间 |
| 模型配置 | 可复用连接配置、任务映射、调用记录 |

题目快照用于支撑交流和证据，不等于建设可独立运营的题库。无具体原题的复测关联知识疑点和历史证据，不伪造来源题目。

### 12.3 结构化输出

识别、解答判定、诊断、变式、复核与知识状态更新使用明确的结构化协议并校验。字段需区分用户犹豫、模型不确定、未判定状态、来源及依据。

不能从长篇自然语言中靠正则提取关键业务状态。无答案时不能仅用布尔值强行表达对错；校验失败不得写入有效学习证据。密钥由本地后端安全处理，不写入普通日志、文档或前端打包内容。

### 12.4 技术选择

原文的 Python、FastAPI、Pydantic、SQLite 与 React 等可作为候选，具体在建设时结合环境选择。目标是本地易启动、数据易维护、模型易替换，第一版不要求迁移到服务端数据库。

原文的题库服务、Optional 空目录和大量功能开关不照搬，不为暂缓功能搭建空壳系统。

## 13. 失败处理与连续性

- 单题识别或求解存疑：该题待确认，其余正常展示。
- 识图完成后诊断失败：保留结果，只重试失败步骤。
- 变式生成或复核失败：不计为用户作答，不更新知识状态。
- 刷新或离开后：已完成内容保留；未完成步骤显示真实状态，可恢复或重试，不伪装成功。
- 换模型重试：复用可用输入，避免重复创建学习证据。
- 自动重试有上限；超过后用户决定再试或换模型，不后台无限消耗。
- 记录修正、证据撤销与知识状态重评保持一致，不能只改显示文案。

## 14. 验收标准

使用真实已作答题页，覆盖不同专业科目、单选、多选、判断及含计算的选择题；连续多轮验证，而不只演示单次问答。

| 场景 | 应达到的行为 |
| --- | --- |
| 上传含 5～10 题的一页 | 分离题目与用户作答，直接给整页反馈，不强制逐题确认 |
| 正确且无犹豫 | 每题一句知识点，不自动长解析 |
| 正确但没思路 | 直接通过，不据此认定知识点掌握 |
| 正确但思路有误 | 简短指出具体问题 |
| 正确且犹豫 | 直接给简短辨析；未说明纠结点时不编造 |
| 错误且诊断无足够证据 | 不强行归因，追问可跳过 |
| 提示优先与切换 | 避免提前揭晓；随时看答案或切换；帮助情况被记录 |
| 多选少选或错选 | 准确区分作答结果，不直接等同于认知原因 |
| 用户主动追问答对题 | 允许交流、看解析、选择变式，无额外门槛 |
| 未请求变式 | 不自动出题；答对变式后不自动追加 |
| 变式质量检查 | 展示前重新求解及核对，不合格题不进入有效训练 |
| 连续答错 | 拆小卡点、保持用户控制，不按次数自动增加篇幅 |
| 新页出现旧知识点 | 联系已有证据，以新表现更新、收窄或修正判断 |
| 用户说懂了或想改状态 | 表示理解不算验证；状态验证需要相关答题证据 |
| 基础验证与深入测试 | 用户主动开始，可返回原题；新条件失败不覆盖基础证据 |
| 尚无证据的知识 | 明确尚无记录，不生成虚假掌握百分比 |
| AI 判错或识别错误 | 修正判定、相关证据与知识状态，不要求用户额外证明 |
| 争议或失败 | 暂不更新知识状态，有限重试且不重复计入证据 |
| 按任务更换模型 | 任务使用指定模型，历史和知识状态连续保留 |
| 历史与删除 | 可恢复对话，删除范围明确，剩余证据与状态一致 |
| 考纲后补 | 可调整框架与范围，保留历史证据，考频不冒充掌握度 |

## 15. 建设阶段的推进顺序

本节仅规定后续先后关系，不构成当前开发授权。

1. 建立本地对话、题目快照、作答、知识节点与证据的基本存储，以及任务模型配置。
2. 打通真实整页图片 → 识别 → 独立解题 → 比对 → 整页反馈，尽早验证主体验。
3. 加入自由追问、反馈偏好、识别修改、争议处理及连续保存。
4. 实现跨次知识状态、相关历史提取、面板及有依据的状态更新。
5. 加入用户自选变式、必需复核、复测、直接前置知识验证和深入测试。
6. 完成资料补充、删除一致性、失败恢复与按任务切换模型的验证。
7. 使用多科真实题页开展连续验收，检查准确性、阅读负担、历史联系及调用成本。

测试和错误处理随各阶段完成，不集中留到末尾。建设时按以上最终范围编写实施方案，不再按原文“先建题库、学习者模型后续再做”的路线执行。
