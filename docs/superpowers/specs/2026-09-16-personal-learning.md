# Personal learning, review and collection — approved discussion

User approved implementation after the design discussion. Work in the existing local product; no cloud deployment, payments, public community, generated questions or core knowledge content authoring.

## Learning

AI classifies question demands, never inferred psychological error causes. Classify against controlled knowledge IDs and method labels, estimated basic/intermediate/advanced difficulty and distinguishable conditions. Missing/low-confidence metadata stays ungrouped. Grouping is a reversible projection, never deletion. Choose a bounded set of representative historical questions per knowledge/method/conditions; repeated copies cannot earn more credit. Keep individual due dates and outcomes. A representative's success does not pass its siblings. Prefer a basic representative without prior evidence; progress to harder examples after independent cross-day success, step down after failure/help. Show all originals separately and allow correction of classification.

Support only currently implemented single/multiple/judge answer types. Never introduce string-equality grading for essays. Use Asia/Shanghai calendar days. Keep help exposure and recent-answer exposure guards. Browsing is not passing. Add hint option to review with no answer leakage. Default daily recommendation is 5 questions, allow 3/5/10; do not silently reschedule excess items. Offer explicit AI organization of existing unclassified questions, bounded per request, with safe failure/retry. New solves include optional classification with no extra model round trip; metadata failure must not invalidate a valid answer.

## Knowledge and retrieval

Full teaching cards for personally linked nodes; no public full core catalog/source file export. Linked draft nodes are visible as unfilled, never fabricated. The server may retrieve any published core node required by the current problem. Hide unlinked relations/candidate catalog from user projections. Local single-user product remains local; not a production multi-tenant security claim.

Core content is answer evidence; personal history is experience, not authority. Solving remains independent of the student's prior wrong answers. Follow-up explanation retrieves at most two related personal historical questions, with both earlier errors and later improvements, original IDs/revisions/dates. Works without published wiki text. Hint/hidden-answer mode must not receive historical answers/explanations or leak history through UI. History failure must not block solving. No model-generated prose silently becomes a core teaching card. Deleted/revised/disputed material is excluded or invalidated. Internal audit records retrieved core IDs/versions and history IDs/revisions and configured model identity, never keys. Citations mean retrieved references, not proven sentence-level attribution. Ordinary explanation prose must not announce wiki vs model origin. Optional collapsed references, essential incomplete/pending warnings remain.

## Archive and appearance

One personal archive, a small collection of evidence-backed medals, and a downloadable share card. Paper and blueprint themes scope only to archive/medals/share output, not study UI. Editable nickname/signature; allow choosing only earned medals. Share defaults omit raw questions, images, correctness, dates and personal detail beyond explicitly selected display fields; preview before local download, no public posting. No arbitrary HTML/CSS/JS theme import, no new paid dependencies. No synthetic mastery scores. Suggested medals: first linked analyzed question; first cross-day original-question review; previously wrong original independently passed on a later day. Recompute eligibility from live valid events, source revisions and current valid analyses; deleted/corrected evidence must not continue granting achievements. Theme never changes eligibility. Render attractive inline vector artwork, no need generated bitmap assets.

## Verification

Failing tests before behavior changes, backend and frontend regression suite, build, knowledge validator, browser smoke on an isolated fixture where practical. Keep real user's sessions/images/API keys private. Backup database before restarting changed service. Local Git checkpoint, no push.
