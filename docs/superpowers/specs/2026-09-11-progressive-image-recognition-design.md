# 渐进式图片识别展示设计

**状态：** 已确认  
**日期：** 2026-09-11

## 目标

用户上传已作答题图后，Kimi 图片模型完成识别便立即展示题目、选项和用户作答；GLM 的独立解题和诊断在此后自动继续。页面不再等待整页分析完成才显示内容。

本次只改善首批可见结果的等待体验，不改变模型选择、提示词、答案判定、知识证据规则或批量分析策略。

## 方案与边界

采用两阶段 HTTP 流程，而非后台常驻任务或 SSE/WebSocket 推送：

1. 前端上传图片后调用新的“仅识别”接口。
2. 后端调用图片模型、保存附件识别状态和题目草稿，并将会话标为已识别待分析。
3. 接口返回后，页面立即显示题目、选项、作答、识别备注和“正在独立解题与诊断”的状态。
4. 前端在下一轮事件循环自动调用现有分析接口；该接口跳过已完成的识别，只执行 GLM 批量解题与批量诊断，随后写入分析和学习证据。

原有 `POST /api/sessions/{sid}/analyze` 保持可用：对尚未识别的附件仍执行完整流程；对已识别题目则只继续分析。这保证旧调用方、手动“重试分析”以及中断后的恢复路径不受破坏。

## 会话状态与恢复

会话增加一个明确的已识别待分析状态（命名在实现中与现有状态枚举统一）。状态含义如下：

| 状态 | 页面含义 | 可恢复行为 |
| --- | --- | --- |
| `recognizing` | 图片正在由 Kimi 识别 | 等待本次请求结束或重试 |
| `extracted` | 题目和作答已保存，尚未分析 | 自动开始分析；重新打开会话时可继续分析 |
| `analyzing` | GLM 正在批量解题与诊断 | 等待、查看已识别题目，或在失败后重试 |
| `ready` | 已有完整分析 | 正常学习流程 |
| `error` | 最近阶段失败 | 保留已成功的识别或分析内容，提供对应阶段重试 |

若 Kimi 识别失败，保留原图并允许再次识别。若 GLM 分析失败，保留识别出的题目和用户作答，重试不重新调用 Kimi。用户编辑识别结果后，既有规则继续撤销相应分析与证据；用户再主动分析时使用编辑后的题目。

## 页面行为

上传后立即显示阶段提示；当识别接口返回时，页面更新为题目总览。未分析题目不显示对错、答案或虚构诊断，而显示“已识别，正在分析”。右侧题目面板仍可让用户核对和编辑识别内容。

前端在渲染识别结果后自动启动后续分析。该自动操作只触发一次；若页面刷新、关闭或网络中断导致它未开始，会话保持 `extracted`，下次打开时恢复分析。已有的进行中会话轮询继续用于刷新 `analyzing` 和最终结果。

## API 与实现边界

新增 `POST /api/sessions/{sid}/extract`，它只执行附件识别和题目持久化，返回公开会话。`POST /api/sessions/{sid}/analyze` 不新增模型调用阶段：它发现附件已提取时直接进行已有的批量解题和批量诊断逻辑。

服务层将识别步骤从整页分析编排中抽为可独立调用的方法。会话锁仍然确保同一会话同一时间只有一个模型操作；接口不会在单个 HTTP 请求中启动无法恢复的后台协程。

## 验收与测试

- 识别接口只调用图片模型，不调用解题或诊断模型。
- 识别成功后返回的公开会话包含题目，且每题尚无分析和学习证据。
- 随后的分析跳过图片模型，调用批量解题与批量诊断，并形成原有结果与证据。
- 分析失败时已识别题目仍可读取，重试不会重新识别图片。
- 前端上传流程先渲染识别结果，再发起后续分析；未分析题目有明确的处理中展示，且不会泄露答案。
- 既有完整 `/analyze` 流程和全部安全、提示模式、证据边界测试保持通过。

## 非目标

- 不承诺 Kimi 识别一定在十几秒内完成；首批可见结果的下限仍由该次图片模型响应决定。
- 不实施 token 流式展示、SSE/WebSocket、后台任务队列或逐题实时推送。
- 不改变当前 Kimi 负责识图、GLM 负责后续任务的模型配置。
