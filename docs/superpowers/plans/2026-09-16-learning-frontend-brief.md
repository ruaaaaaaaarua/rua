## Visual direction and integration checks

Treat the archive as a designed personal object, not a grid of generic KPI cards. Paper: warm paper cover, ink typography, embossed/stamp-like medal rings, thin ruled separators. Blueprint: deep navy cover, restrained cyan linework and drafting ticks, legible high-contrast body. Use a clear cover title, small bilingual archival labels only where useful, generous spacing and a collected-medal shelf. Avoid confetti/constant motion, fake serial numbers, fake affiliation with State Grid, or claims of certified ability. Three medals should use distinguishable vector motifs (connection, sunrise/calendar, restored circuit), not only different colors. Show truthful empty/locked state when user has no records.

Do not turn saved provenance into unsupported reference links: if a cited node is unlinked, it may be shown as plain reference text but not a broken link to /api/wiki/{id}. Personal history navigation uses App's existing openSession(sid,qid), not an invented browser route. Scope all theme CSS under the archive root. Knowledge search currently relies on aliases but scoped API may omit them; tolerate this. Global App.refresh currently refetches reviews with default limit5; ensure the chosen budget remains effective after any action/refresh. Server can reject a locked/removed medal after an edit; show error and refresh actual eligibility instead of keeping a fake earned preview.
